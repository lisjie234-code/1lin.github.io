Internal Report

关于近两周 AI 工具学习
与景观业务结合的初步汇报

最近两周的业余时间，我初步了解并实操了 OpenClaw、Workbuddy 等 AI Agent 工具。
这次尝试给我最大的收获，其实是一种工作思维的转变。以前实习做项目，总觉得找意向图、整理案例等"体力活"就该自己熬夜干。但接触 Agent 后我发现，完全可以把 AI 当成我的"虚拟实习生"。我的主要精力应该放在"如何下达准确指令"以及"判断结果是否可用"上。这种从"纯画图"变成"小包工头"的效率思维，让我觉得非常有必要向您简单汇报一下近期的尝试与设想：

01
工具摸索与踩坑经验
算力分配（放弃本地，拥抱云端）

一开始我尝试在本地部署 Ollama（跑 Llama 3 等），但极其消耗电脑内存，导致画图时卡顿。因此现阶段建议弃用本地算力，直接调用云端 API 接口，保证工作流顺畅。

各家模型实测与组合使用

这段时间对比测试了几款主流大模型，整体思路是"对症下药"，根据不同需求组合使用。

国产三件套 高性价比
MiniMax 2.7、Qwen 3.6 Plus、DeepSeek 3.2——处理基础任务划算，能有效控制成本。
Claude 逻辑首选
写代码和梳理复杂逻辑上更聪明，但对 VPN 节点限制较严，开通会员有一定门槛。
Gemini / Nano Banana 搜索 + 生图
查资料体验顺滑，Nano Banana 模型生图效果不错，可直接用于方案配图。
认清"折腾成本"

这半个月遇到过刚配好的环境一更新就报错，也遇到过用爬虫抓图被网站封堵。OpenClaw 学习速度赶不上升级速度，版本迭代迅速，目前刚体验 4.6 版本，出现系统崩溃、UI 界面卡顿等严重现象。这让我明白，搞技术工具的前期维护成本很高。如果未来要在团队推广，必须先剔除这些不稳定因素，拿出一个"傻瓜式"的稳定版本，避免增加大家的负担。

02
自动化流的初步跑通

在明确了模型方向后，我跟着教程初步跑通了一些基础应用：

了解运行机制与身份设定

初步弄懂了 Agent 的运转逻辑，能够通过修改 soul 和 agents.md 配置文件，给 AI 设定特定的"职业身份"来处理问题。

跨平台联动

试着安装了微信、飞书和 QQ 的插件，初步看懂了 AI 是如何联动这些聊天软件发送消息的。未来可以用飞书、QQ 等多 Agent 协调工作。

Workbuddy 深度体验

这是目前用下来效果最好、运行也最稳定的一个工具。支持本地一键部署，基本是"傻瓜式"操作，不需要翻墙就能直接用，各类技能也是一键就能配置好，非常契合日常办公场景。

  • 功能页面已全面摸熟，能灵活为不同模块接入不同大模型
  • 系统自带 Skill 技能库充足，基本覆盖日常需求；特殊需求可在 Cloudhabit 下载社区插件
  • 正在尝试跑通小红书抓取 Skill，用于快速搜集爆款景观案例和大众反馈——目前受平台反爬虫机制限制，持续调试中
  • 深入研究 AI 上下文记忆 / 长期记忆整合，以及"自我反思"与"学习提升"机制，目标是建立个人知识库
进行中：小红书 Skill 调试 进行中：知识库构建
03
结合景观设计业务的落地规划

结合上述摸索，我认为这套工具可以在未来逐步赋能景观设计工作，具体分为"个人辅助"与"团队共享"两个阶段：

Phase 01 · 近期设想
个人工作流提效
  • 配置"景观搜索小助手"：尝试写出一个能自动扒场地调研数据、查规范的专属 Skill，缩短前期找资料的时间
  • 塞进日常工作流：前期辅助找灵感意向，中期帮着理顺文本逻辑，后期尝试辅助优化排版
Phase 02 · 长远设想
搭建迷你"AI 景观虚拟部门"
  • 封装团队通用"景观基础 Skill"：给 AI 写好针对行业的行为准则，同事直接调用无需懂底层代码
  • 拆分各司其职的"虚拟员工"：前期调研专员、项目文案策划、施工落地审核员
  • 多 Agent 协同"开会"纠错：调研专员拉完数据出方案，直接交给审核员挑刺，交叉验证过滤不靠谱想法

目前我还在初期的学习和摸索阶段，后续如果有更成熟的稳定版本，我再向您和团队做详细演示。
